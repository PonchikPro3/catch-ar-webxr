# Поймай объект / Catch AR

Прототип мини-игры в дополненной реальности на Unity **6000.3.11f1 LTS**, URP **17.3.0** и **unity-webxr-export 0.25.0**.

**Игра:** https://ponchikpro3.github.io/catch-ar-webxr/

**Репозиторий:** https://github.com/PonchikPro3/catch-ar-webxr

## Быстрый запуск готовой сборки

1. Открой PowerShell в папке проекта.
2. Выполни `powershell -ExecutionPolicy Bypass -File .\Start-CatchAR.ps1`.
3. Открой **http://localhost:8080**. Нужен установленный Node.js.
4. На телефоне с WebXR нажми **«Играть»**. Для проверки мышью в Unity Editor открой сцену `Assets/CatchAR/Scenes/CatchAR.unity` и нажми Play, затем «Играть».

Файл `Builds/WebGL/index.html` нужно открывать через сервер, а не двойным щелчком.

После клонирования из GitHub готовая сборка находится в `docs/`; скрипт запуска автоматически использует её, если локального `Builds/WebGL` ещё нет.

## Запуск настоящего AR

Открой [GitHub Pages](https://ponchikpro3.github.io/catch-ar-webxr/) на устройстве с поддержкой `immersive-ar`, например Android с ARCore и совместимым Chrome. Кнопка «Играть» сразу запрашивает AR. Если браузер не поддерживает WebXR AR, игра показывает подсказку о совместимом телефоне; в демо автоматически не переключается.

1. Нажми **«Играть»**, разреши доступ к камере.
2. Направь телефон на **пол** и немного перемести его; вертикальные поверхности не принимаются за землю.
3. Когда появится маркер, коснись экрана, чтобы зафиксировать уровень земли.
4. Если пол не обнаружен, через 5 секунд можно продолжить: предполагаемый уровень земли будет на 1,5 м ниже камеры.
5. После отсчёта держи телефон перед собой и смотри вокруг. Все объекты появляются на одинаковом расстоянии **2,5 м от камеры**, на **0,5 м выше неё**. Первый объект появляется перед игроком, следующие — по окружности вокруг него. Нажимай на них до касания земли. На XR-устройстве используется луч контроллера и Trigger.
6. Небольшие стрелки у краёв экрана показывают направление к объектам вне поля зрения. Поверни телефон в указанную сторону. Оранжевая стрелка ведёт к обычному объекту, кремовая — к бонусному; при появлении цели в кадре стрелка исчезает.

Для телефона `http://<IP компьютера>:8080` не является защищённым контекстом. Используй HTTPS-хостинг. `localhost` подходит для локальной проверки на самом компьютере.

## Правила

- Раунд длится **60 секунд**.
- Красно-оранжевый объект: **10 очков**. Каждый пятый, кремовый бонусный: **25 очков**.
- Последовательные поимки с интервалом до 1,8 секунды повышают множитель до **×5**.
- Расстояние появления всегда 2,5 м, высота — 0,5 м над камерой. Случайные радиусы и высоты исключены. После появления объекты падают с ускорением, сохраняя своё положение по горизонтали.
- В версии 1.3.1 падение замедлено примерно на четверть: начальная скорость 0,28 м/с, ускорение 0,14 м/с². Время в воздухе определяется расстоянием до пола; отдельного таймера удаления нет.
- Нажатие ловит объект, начисляет очки и удаляет его со сцены.
- После касания видимой моделью земли объект за 0,25 с уменьшается и исчезает без очков; счётчик «Упало» увеличивается один раз. Промах или падение сбрасывает серию.
- В AR новые объекты появляются на 360° вокруг текущего положения игрока. В демо они падают перед фиксированной камерой.
- Указатели помогают найти цели за пределами кадра, включая объекты за спиной. Они не перехватывают нажатия и исчезают после поимки или падения объекта.
- Одновременно на сцене находится до пяти объектов; скорость появления постепенно растёт.
- Рекорд хранится локально через `PlayerPrefs`.
- После завершения доступны повторный раунд и меню. В AR следующий раунд также запускается касанием после показа результата.

## Открытие и повторная сборка в Unity

Добавь папку `CatchAR` в Unity Hub и открой Unity **6000.3.11f1** с модулем **Web Build Support**.

- Основная сцена: `Assets/CatchAR/Scenes/CatchAR.unity`.
- Повторная сборка: меню **Catch AR → 2. Build WebGL**.
- Пересоздание исходной сцены: **Catch AR → 1. Create prototype scene**. Этот пункт заменяет текущую сцену; для обычного запуска он не нужен.
- Сборка сохраняется в `Builds/WebGL`.
- Итог Unity BuildReport и ключевые настройки сохраняются в `Evidence/build-report.json`.

## Обновление GitHub Pages

GitHub Pages раздаёт каталог **`docs/` ветки `main`**. После новой сборки скопируй содержимое `Builds/WebGL` в `docs/` и отправь изменения в GitHub. Файл `docs/.nojekyll` отключает обработку Unity-файлов через Jekyll. Серверная часть не требуется.

## Выполнение требований

| Требование | Реализация |
|---|---|
| unity-webxr-export установлен | `com.de-panther.webxr` 0.25.0 подключён через Unity Package Manager из `Vendor/WebXR` |
| Пакет подключён к XR | `WebXRLoader` назначен WebGL в XR Plug-in Management; конфигурация хранится в `Assets/XR/Settings` |
| Камера WebXR | `WebXR Camera Rig` содержит `WebXRManager`, `WebXRCamera`, `TrackedPoseDriver` для отслеживания головы и пять назначенных камер Desktop/VR/AR |
| WebXRController | Два компонента для левой и правой руки; игровой ввод использует `GetButtonDown(Trigger)` и raycast |
| WebGL | Готовая сборка в `Builds/WebGL`; используется шаблон `PROJECT:CatchAR` |
| Compression fallback выключен | `PlayerSettings.WebGL.decompressionFallback = false` |
| Multithread выключен | `PlayerSettings.WebGL.threadsSupport = false` |
| Простой локальный хостинг | Сжатие сборки выключено: `compressionFormat = Disabled`, сервер задаёт MIME `application/wasm` |

Экспортёр использует документированный режим `DisableXRDisplaySubsystem = true` с компонентом `WebXRCamera`. Для AR назначены отдельные прозрачные камеры; постобработка применяется только к демонстрационной камере. Поиск поверхности использует `OnViewerHitTestUpdate`, реальное окружение показывает браузерная AR-сессия.

## Исходный код

- `CatchGame.cs`: состояния игры, таймер, очки, размещение, WebXR-ввод.
- `CatchTarget.cs`: ускоренное падение, поимка и исчезновение на уровне земли.
- `CatchHud.cs`: интерфейс, результат, кнопки.
- `OffscreenIndicators.cs`, `OffscreenArrow.cs`: направления к целям вне кадра и небольшие стрелки у краёв экрана.
- `PrototypeBuilder.cs`: создание сцены, подключение XR, настройки и сборка.
- `Assets/WebGLTemplates/CatchAR/index.html`: загрузка Unity, проверка WebXR и запуск AR из пользовательского жеста.

Исходный [unity-webxr-export](https://github.com/De-Panther/unity-webxr-export) зафиксирован на теге `webxr/0.25.0`, commit `6bb0f2c09abfd089409da64da447f582948853c9`. Код пакета и его лицензия сохранены в `Vendor/WebXR` без изменений. Локальная зависимость делает проект переносимым без повторного скачивания экспортёра из GitHub. Остальные зависимости Unity восстановит через Package Manager.

[Инструкция автора по подключению](https://github.com/De-Panther/unity-webxr-export/blob/master/Documentation/Getting-Started.md) описывает XR-провайдер и необходимость HTTPS/localhost.

## Интерфейс 1.4

- `Assets/UI.png` — исходный sprite sheet пользователя. Спрайты рамки, часов, двух кнопок и эффекта из трёх палочек сохранены в `Assets/CatchAR/Art/UI/`; исходное изображение не перерисовано. Контур кнопок отсекает соседние элементы листа.
- Палитра: `#FF4545`, `#FF9867`, `#FFBF87`, `#FFEDB2`. Тёмный нейтральный цвет текста и обводки обеспечивает читаемость поверх камеры.
- В стартовом меню только «Играть» и «Выход». HUD содержит настоящий `UnityEngine.UI.Slider`, часы сбоку и одну цифру счёта по центру под ним. Старые карточки, режим, рекорд, серии и текстовые вспышки удалены с экрана; правила подсчёта очков сохранены.
- Часы покачиваются при каждом отсчёте секунды; последние 10 секунд усиливают пульсацию часов и полосы. Очки плавно пересчитываются, цифра подпрыгивает и слегка поворачивается. При поимке в точке касания появляется один спрайт из трёх палочек с увеличением и затуханием.
- Размещение: подсказка поиска пола и оформленная кнопка «Разместить». Завершение раунда: итоговое число, «Ещё раз» и «В меню».
- «Выход» завершает Unity. Обычную вкладку браузер может запретить закрывать скриптом — тогда остаётся экран «Игра завершена» с предложением закрыть вкладку.
- Повторно применить оформление: меню Unity **Catch AR → Apply sprite UI**. Сцена сохранена; для запуска генератор не нужен. Демонстрационное управление мышью доступно при запуске в Editor.

## Исправление ввода 1.4.1

Касание и мышь обрабатываются до лучей контроллеров, после обновления движущихся объектов и EventSystem. UI проверяется отдельным GraphicRaycaster в текущей точке касания, без кеша прошлого кадра. Поимка использует текущие границы видимых моделей и фактическую проекцию WebXR; зона касания имеет небольшой допуск. Из наложенных целей выбирается ближайшая, цели за камерой и уже упавшие исключены. Луч контроллера работает и при начале внутри границ модели.

При приближении игрока к падающему объекту ближе 1 м по горизонтали объект отодвигается на безопасное расстояние. Проверка выполняется также перед рендерингом, после обновления XR-позы. Новые объекты по-прежнему появляются на фиксированной дистанции.

Проверки: `Evidence/input-fix-check.txt`; временный сценарий проверки находится в `Temp/UIReview/InputFixChecks.cs`, в сборку не включён. Физическое AR-устройство в среде проверки недоступно.
